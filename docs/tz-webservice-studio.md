## 1. Общая информация о проекте

### 1.1 Описание

Сайт web-service.studio — рабочий сайт веб-студии, который требует обновления: современный дизайн, полноценный бэкенд для самостоятельного ведения блога и портфолио, форма связи с уведомлениями в Telegram, а также раздел услуг и цен. Ключевое требование — **простота переноса на текущий хостинг**, на котором сайт уже работает.

### 1.2 Цели проекта

- Обновить дизайн сайта до современного уровня, сохранив узнаваемый фирменный стиль (логотип и цветовая палитра студии).
- Дать студии инструмент для самостоятельного ведения блога и портфолио без участия разработчика.
- Наладить приём заявок с сайта с мгновенным уведомлением в Telegram-канал.
- Представить полный перечень услуг и цен, включая узкоспециализированные направления (арбитраж трафика).
- Обеспечить хорошую видимость сайта в поисковых системах и корректные превью при шаринге в соцсетях.
- Сделать сайт лёгким для переноса между хостингами.

### 1.3 Целевая аудитория

- Владельцы бизнеса и стартапы, которым нужен сайт или лендинг.
- Арбитражники трафика, которым нужны вайтпейджи, лендинги, клоакинг.
- Владельцы доменов/сайтов, которым нужно администрирование.

### 1.4 Технологии, зафиксированные заказчиком

| Параметр | Решение |
|---|---|
| Backend | PHP 8.5 (самописный, без тяжёлого фреймворка — для максимальной совместимости с хостингом) |
| СУБД | MySQL / MariaDB |
| Подход к рендерингу | Серверный рендеринг (SSR) классическими PHP-шаблонами — без Node.js-сборки на проде |
| Frontend | HTML5, CSS3, минимум внешних JS-зависимостей; сборка (если используется) — только на этапе разработки, на хостинг заливаются готовые файлы |
| Админ-панель | Отдельная защищённая область `/admin`, тот же PHP-стек |
| Система контроля версий | Git, приватный репозиторий на GitHub — код версионируется отдельно от хостинга, что упрощает перенос и внесение изменений без правок «вживую» на проде |
| Языковые версии | Одна основная версия — украинская. Англоязычная версия — отдельная переведённая копия сайта, готовится на завершающем этапе (см. 3.1 и раздел 7) |

## 2. Общие технические требования

### 2.1 Простота переноса на хостинг (ключевое требование)

- Никаких зависимостей, требующих SSH/CLI-доступа для запуска в проде (без Docker, без обязательного Composer на сервере — при использовании Composer вендорные библиотеки заливаются вместе с проектом).
- Все настройки окружения (доступы к БД, токен Telegram-бота, домен, режим debug/production) — в одном конфигурационном файле (`.env` или `config.php`), не входящем в репозиторий по умолчанию.
- Полный дамп структуры и данных БД (`.sql`) поставляется вместе с проектом и обновляется при сдаче.
- Понятная файловая структура, готовая к заливке по FTP/файловому менеджеру хостинга.
- Инструкция по установке/переносу (пошагово: создать БД → импортировать дамp → прописать конфиг → выставить права на папки → указать сайт в панели хостинга).
- Минимальные требования к хостингу фиксируются отдельным пунктом в приёмо-сдаточной документации (версия PHP, наличие MySQL, mod_rewrite, поддержка SSL) и заранее сверяются с текущим хостингом заказчика.
- Весь код проекта хранится в приватном репозитории на GitHub. Это даёт историю изменений, возможность отката, совместную работу над кодом и исключает ситуацию, когда единственная актуальная версия сайта существует только на хостинге.
- Деплой на хостинг — из репозитория: сайт работает на **Hostinger**, который поддерживает SSH-доступ и встроенный Git-деплой через hPanel. Обновления накатываются через `git pull`/встроенный Git-деплой hPanel — ручная заливка по FTP используется только как запасной вариант.

### 2.2 Кроссплатформенность и кроссбраузерность

- Адаптивная вёрстка (mobile-first): корректное отображение на смартфонах, планшетах, десктопах.
- Поддержка последних двух версий Chrome, Firefox, Safari, Edge, а также мобильных Safari (iOS) и Chrome (Android).
- Проверка на реальных устройствах/эмуляторах перед сдачей.

### 2.3 PWA (Progressive Web App)

- `manifest.json` с иконками нескольких размеров (на основе предоставленного логотипа), именем, цветом темы, стартовым URL.
- Service Worker: кэширование статики и ключевых страниц, корректная работа офлайн-заглушки при отсутствии сети.
- Возможность «Установить на главный экран» на мобильных устройствах и десктопе.
- Прохождение базового PWA-чек-листа Lighthouse (Installable, HTTPS, offline fallback).

### 2.4 Безопасность

- Все SQL-запросы через подготовленные выражения (PDO/prepared statements) — защита от SQL-инъекций.
- Защита форм от спама (honeypot-поле и/или капча) и от CSRF (токены на формах).
- Экранирование пользовательского ввода при выводе (защита от XSS).
- HTTPS обязателен на всех страницах.
- Защищённый доступ в админ-панель (логин/пароль, хэширование паролей, ограничение попыток входа).
- Резервное копирование БД и файлов — рекомендации в документации по деплою.

### 2.5 Производительность

- Оптимизация и адаптивная отдача изображений (в т.ч. современные форматы, например WebP при наличии поддержки).
- Минификация CSS/JS.
- Кэширование статических ресурсов на уровне сервера/браузера.
- Целевые показатели: Google PageSpeed/Lighthouse Performance ≥ 90 для мобильной и десктопной версий.

## 3. Карта сайта (структура разделов)

1. **Главная** — оффер студии, ключевые услуги, избранные кейсы, преимущества, призыв к действию, последние статьи блога.
2. **Услуги** — общий обзор с переходом в подкатегории:
   - Разработка сайтов (лендинги, корпоративные сайты, интернет-магазины и т.п.)
   - Разработка приложений под Android
   - Услуги для арбитража трафика: вайтпейджи, лендинги (ленды), клоакинг
   - Настройка и администрирование доменов и сайтов
3. **Цены** — тарифы/пакеты по каждому направлению услуг (управляются из админки).
4. **Портфолио / Работы** — карточки кейсов с фильтром по типу услуги, описанием, изображениями, (опционально) ссылкой на результат.
5. **Блог** — лента статей, страница отдельной статьи, категории/теги, поиск по блогу.
6. **О студии** — информация о команде/подходе (опционально, если нужно заказчику).
7. **Контакты** — форма связи, реквизиты, ссылки на мессенджеры/соцсети, карта (при необходимости).
8. **Политика конфиденциальности** — обязательна из-за формы сбора персональных данных.
9. **Служебные страницы** — 404, sitemap.xml, robots.txt.
10. **Админ-панель** (`/admin`, не индексируется) — управление блогом, портфолио, услугами/ценами, входящими заявками.

### 3.1 Языковые версии

- **Основная версия сайта — украинская.** Именно на ней ведётся вся разработка, наполнение блога/портфолио и тестирование. Мультиязычный переключатель и мультиязычная база данных в CMS **не проектируются** — это упрощает архитектуру бэкенда (одно поле контента на сущность вместо набора переводов).
- **Англоязычная версия — отдельная полная копия сайта**, которая делается на завершающем этапе, после того как украинская версия полностью готова (весь функционал реализован, контент наполнен, всё протестировано) — непосредственно перед сдачей проекта. Копия переводится на английский и размещается отдельно от основной версии.
- Размещается в подпапке `web-service.studio/en/` (решение зафиксировано заказчиком). Между украинской и английской версией нужно проставить `hreflang`-теги, чтобы поисковики корректно понимали, что это языковые версии одного сайта.
- Текущий переключатель языков UA/EN/RU на старом сайте в новой версии не сохраняется — вместо него будут ровно две отдельные версии сайта: UA (основная) и EN (копия).

## 4. Функциональные требования по разделам

### 4.1 Блог

- Админка: создание/редактирование/удаление статей, черновики и публикация, категории и теги.
- WYSIWYG-редактор текста, вставка изображений в статью.
- Для каждой статьи — свои SEO-поля: title, meta description, og-изображение, ЧПУ-адрес (slug).
- Публичная часть: лента с пагинацией, страница категории/тега, страница статьи, похожие статьи, дата публикации.
- Возможность периодически добавлять новые статьи без участия разработчика — ключевое требование заказчика.

### 4.2 Портфолио (Работы)

- Админка: добавление/редактирование/удаление кейсов — изображения (обложка + галерея), название, описание, категория услуги, ссылка на проект (опционально), сортировка отображения.
- Публичная часть: сетка кейсов с фильтром по категории услуги, страница отдельного кейса.

### 4.3 Услуги и цены

- Раздел услуг **полностью управляется через админку** — так же, как блог и портфолио, без участия разработчика: добавление, редактирование и удаление услуг и категорий услуг, а не только правка цен.
- Для каждой услуги в админке редактируются: название, описание, категория, стоимость/диапазон цен или пакет, порядок отображения, статус (опубликована/скрыта).
- Явные разделы/категории (задаются изначально, но остаются редактируемыми):
  - Разработка сайтов
  - Разработка приложений под Android
  - Арбитраж трафика: вайтпейдж, лендинги, клоакинг
  - Администрирование доменов и сайтов
- Для каждой услуги — заявка «Заказать» ведёт на форму связи с предзаполненной темой.
- **Цены на старте:** пока раздел заполняется ориентировочными ценами/диапазонами на уровне среднерыночных по Украине, без точных финальных цифр. Как только админка раздела «Услуги» будет готова (этап 4, раздел 7), заказчик самостоятельно проставит реальные тарифы по каждой услуге (включая Android-разработку) через интерфейс — без участия разработчика, и в любой момент сможет их скорректировать.

### 4.4 Форма связи и уведомления в Telegram

- Поля формы: имя, контакт (email/телефон/мессенджер), интересующая услуга, сообщение.
- Валидация на фронтенде и на бэкенде, защита от спама (honeypot/капча).
- При успешной отправке — уведомление **мгновенно приходит в Telegram-канал** через Telegram Bot API. Бот и канал уже настроены заказчиком; токен бота и chat_id хранятся в конфиге окружения на сервере (`.env`/`config.php`), не публикуются в этом документе и не коммитятся в Git-репозиторий — переданы отдельной технической заметкой в проекте.
- Заявка дополнительно сохраняется в БД и отображается в списке заявок в админ-панели (с отметкой «новая/обработана»).
- Опционально: дублирование заявки на email студии.

### 4.5 Админ-панель

- Авторизация по логину/паролю.
- Разделы: Блог, Портфолио, Услуги и цены, Заявки с формы, (опционально) базовые настройки сайта (контакты, соцсети, SEO по умолчанию).

## 5. SEO-требования (поисковики и соцсети)

- Редактируемые title и meta description для каждой страницы, статьи блога и кейса портфолио.
- Open Graph и Twitter Cards — корректные превью (заголовок, описание, изображение) при шаринге ссылок в Facebook, Telegram, X (Twitter), LinkedIn и т.д.
- Семантическая HTML5-вёрстка, микроразметка Schema.org (Organization, Article — для статей блога, BreadcrumbList, Service — для услуг).
- Автоматически формируемый **sitemap.xml**, обновляющийся при добавлении новых статей/кейсов.
- **robots.txt** с корректными директивами (открыт для основных страниц, закрыт для `/admin` и служебных путей).
- Человекопонятные URL (ЧПУ) для всех страниц, статей и кейсов.
- Canonical-ссылки для предотвращения дублей контента.
- Быстрая загрузка страниц (см. раздел 2.5) как фактор ранжирования.
- Корректные favicon и иконки для соцсетей/мобильных на основе предоставленного логотипа.

## 6. Дизайн-требования

- Современный, лаконичный дизайн в фирменной цветовой гамме студии (бирюзовый/циан + белый — по предоставленному логотипу).

- Единый UI-кит: типографика, цветовая палитра, стили кнопок, форм, карточек — для единообразия всех разделов, включая админку.
- Полная адаптивность (mobile-first) под все размеры экранов.

## 8. Критерии приёмки

- Все разделы карты сайта реализованы и наполнены новым контентом.
- Блог, портфолио и раздел услуг полностью управляются из админки без участия разработчика (создание/редактирование/удаление, а не только правка цен и текстов).
- Заявки с формы связи мгновенно приходят в Telegram-канал и сохраняются в БД.
- Раздел цен и услуг отображает все заявленные направления, включая арбитражные услуги.
- Sitemap.xml и robots.txt доступны и корректны.
- Сайт корректно отображается в последних версиях основных браузеров и на мобильных устройствах.
- Сайт проходит базовый PWA-чек-лист (устанавливается на главный экран, работает офлайн-заглушка).
- Сайт успешно перенесён на целевой хостинг по инструкции силами заказчика или его технического специалиста.
- Код проекта находится в приватном репозитории на GitHub, история изменений ведётся с самого начала разработки.
- Готова полная англоязычная копия сайта (создаётся после завершения всех работ над основной украиноязычной версией, перед сдачей проекта).
